NOTE **Depths integrator.** Briefly describe how your code compute the depths. Include the two renderings (PNG images) from your code. Open the `.exr` file with `tev`, what is the (inverse) depth of the two balls in the cbox scene (doesn't need to be very accurate)? My implementation of the `DepthsIntegrator` computes depth by first performing a ray intersection query with `scene.geometry.ray_intersect`. For the rays that successfully hit an object (indicated by a boolean `hit_mask`), the depth value `t` is calculated. Since the `GeometryOutput` does not directly provide `t`, it is calculated using the ray equation `p = o + t*d`. By rearranging this equation, `t` can be solved for with the formula `t = ((p - o) • d) / (d • d)`, where `p` is the intersection point, `o` is the ray origin, and `d` is the ray direction. This is implemented in PyTorch using element-wise multiplication followed by a sum over the vector dimension (`torch.sum(..., dim=1)`) to perform the batched dot products. The final color for each pixel is the inverse of this depth, `1/t`. This grayscale value is then duplicated across the R, G, and B channels. Rays that miss the geometry are assigned a color of black `(0,0,0)`. ![Cornell Box with Depths Integrator](images/cbox-depths.png) ![Ajax Bust with Depths Integrator](images/ajax-depths.png) When viewing the `cbox-depths.exr` file in `tev`, the inverse depth values for the spheres can be read directly from the floating-point pixel data. The front (larger) sphere has an inverse depth of approximately **0.21**. The rear (smaller) sphere has an inverse depth of approximately **0.18**. Taking the reciprocal of these values, these values correspond to actual depths of ~4.76 and ~5.56 respectively, which aligns with the focal distances required to bring them into focus in the thin lens part of the assignment.
!!! NOTE **Thin lens camera.** Briefly describe how your code produce the rays. Include the two renderings (PNG images) from your code. My implementation of the `ThinLensCamera` simulates depth of field by transforming ideal pinhole rays based on lens parameters. The entire process is first performed in camera space, where the camera is at the origin looking down its negative Z-axis. The process begins by generating an ideal pinhole ray to determine the point of perfect focus. This point, `p_focus`, is found by calculating where the ray intersects the focal plane, which is set at a distance of `-focal_distance` from the camera. ```python pinhole_rays_d = self.camera.image_to_camera(coords) ft = -self.focal_distance / (pinhole_rays_d[:, 2:3] + 1e-8) p_focus = pinhole_rays_o + ft * pinhole_rays_d ``` Instead of originating from the pinhole, the new ray's origin is randomly sampled from a square region representing the lens, with its size determined by the `aperture`. ```python lens_radius = self.aperture / 2.0 lens_points_2d = (torch.rand(N, 2, device=coords.device) * 2.0 - 1.0) * lens_radius new_rays_o = torch.cat([lens_points_2d, torch.zeros(N, 1, device=coords.device)], dim=1) ``` With this new origin on the lens and the target `p_focus` on the focal plane, a new direction vector is calculated and then normalized to unit length. ```python new_rays_d = p_focus - new_rays_o new_rays_d = F.normalize(new_rays_d, p=2, dim=1) ``` Finally, this new ray, with its randomized origin and recalculated direction, is transformed from camera space into world space to be traced in the scene. This process is repeated for every sample per pixel. Rays for objects on the focal plane converge correctly, while rays for objects at other distances create a realistic blur when their results are averaged. ![Cornell Box with focus on the front sphere (focal_distance=4.9)](images/depths-front.png) ![Cornell Box with focus on the rear sphere (focal_distance=5.59)](images/depths-back.png) # Other comments !!!
